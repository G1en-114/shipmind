# ShipMind 把一台 DGX Spark 搬上船

> 参赛项目：**ShipMind（智舷）—— 船舶离线值守多智能体副驾**

---

## 引子：一道数学题

198GB。这是 step-3.7-flash（1980 亿参数）用 FP8 精度存放权重的体积。而 NVIDIA DGX Spark 的统一内存是 121GB。

参赛前我们就把这道减法做完了：**再先进的云端大模型，在一条漂在大洋中间的货轮上，都可能因为一条卫星链路的中断而失联**。机舱告警要秒级响应，卫星链路会抖会断；《海上交通安全法》第二十四条还要求我国管辖海域的通信通过境内关口站转接——船上的音视频、AIS、航线数据在船内闭环处理，是合规风险最低的架构。

所以我们的项目从第一天起就锁定了一个别人不太会选的场景：**把一台 DGX Spark 搬上远洋货轮，让所有 AI 在船端离线运行**。一台四万块的设备，对一艘几千万的船，占比相当于船上的火警报警器，但多出来的不是警报，是一整套能听、能看、能查、能说、能记的值守班底。

## 第一天到第三天：从 367 个 Skill 里挑出六个

开营训练营最大的收获不是某个 API 的用法，而是一个判断：**Skill 是 Agent 时代真正沉淀下来的资产**。NVIDIA 官方目录在六个月里收录了 300+ 个 Skill、41 条产品线，每日从产品仓同步——我们决定站在这个生态上，而不是自己造轮子。

于是第一件事就是把官方目录（367 个 Skill）整体搬下来，pin 在上游 commit 上，装了六个和船舶场景相关的：RAG Blueprint、TAO 图像定位、TAO 指代表达、VSS 视频问答、VSS 报告生成、DeepStream 管线生成。

诚实地说：六个里只有一个被我们**真执行**了——DeepStream 管线生成器有零依赖脚本，输入"处理一段机舱录像并做推理"，返回真实的 `gst-launch-1.0 ... nvinfer ...` 管线命令，现在这条命令就在我们的大脑路由里活着。其余五个是"指令型" Skill：它们教 Agent 怎么部署 RAG Blueprint、怎么跑 TAO 管线，但需要 NGC key、TAO 容器、VSS 服务这些前置条件。我们没申请齐，就没让它们先用测试数据跑，桥接层把它们标注为 advisory 模式，展开它们的指令内容并注明缺什么。

## 第四天的事故：我们把自己写的东西搞挂了

这九天里最有价值的一次失败，是我们**自己**造成的。

GB10 的 121GB 内存是 CPU 和 GPU 共用的"统一内存"。我们用 vLLM 起本地推理端点时，沿用了默认参数 `gpu-memory-utilization 0.9`。在独立显存的机器上这没什么问题，但在统一内存架构上，这意味着一个小模型的推理服务**吃掉了全机 90% 的内存**。晚上十点，节点进程调度被饿死，SSH 认证通过但会话建不起来，我们眼睁睁看着自己无法登录自己启动的服务。

三个小时后 Linux 的 OOM killer 自救杀了容器，节点才活过来。我们把三条修正参数（显存限容 0.45、flashinfer 版本检查绕过、enforce-eager）固化进启动脚本，并在事故记录文档里写明：**小模型在统一内存机器上也必须显式限容**。这个坑后来还救了我们一次——起第二个大模型端点做"多模型分工"实验时，看到内存逼近红线，我们直接放弃了，因为知道那是什么后果。

事故的副产品是：vLLM 修好后的**双端点回归对照**跑通了。同一套路由用例（两正一负，负例是"今天晚饭吃什么"必须不触发任何 Skill），分别打本地 Qwen3-4B 和 StepFun 的 step-3.7-flash，6/6 行为一致。这就是"换模型只改三个值 + 回归评测证明等价"的完整实证。

## 第五到七天：数字不会说谎，但会倒挂

技术主体完成后，我们把精力押在评测上——因为评审标准里"智能体与模型优化技术深度"占 25%，而我们对"深度"的理解是：**拿数据说话，包括不好看的数据**。

**声学双轨对照**给了第一个意外。我们实现两条轨：一条启发式（轴承温度、频谱质心、频段能量占比等信号特征做基线偏离度），一条是按 DCASE 2020 官方配方从零重写的自编码器。在真实 MIMII 数据的全量测试集上，启发式三机种全面胜出（pump 0.687 / valve 0.777 / fan 0.630），而自编码器带符号重构误差在 pump 上 **AUC 只有 0.260——比随机还差**。

诊断后发现不是 bug：这个子集的异常是"信号变更弱"（异常段能量反而更低），自编码器把异常重建得更好，误差符号就反了。换成方向无关的偏离度分数后回到 0.602。我们把两种口径都写进报告，不藏结果——因为它证明了一个反直觉的事实：**"异常=重构误差更高"这个领域默认假设，在真实数据上不总成立**。

**视觉模块**给了第二个教训。合成表盘上黑指针的读数曾出现 0.646 的灾难性离群——约 180° 的方向性错误，指向对侧刻度线被误判为指针。我们加了双峰歧义检测（非指针区存在与主峰相当的第二个径向结构就拒判），MAE 从 5.6% 降到 2.0%。代价是拒判率上升，但我们认为**拒判不是失败，是把"我不确定"诚实地说出来**——一个值守系统最危险的行为不是"做不到"，而是"不确定却硬答"。

## 第八天：值班台长出了脸，值班官第一次开口

功能都是真的，但命令行滚 JSON 给评委看像在看别人调试代码。我们把值班台做成了驾驶台风格的 Web 界面：六视图导航、可交互的 360° 雷达 PPI（点目标、切量程）、声学频谱、表盘读数带检测框、手册检索带原文引用、报告导出、执行轨迹回放。

最有仪式感的一刻是"Spark AI 值班官"面板接上本地大脑后第一次输出值班简报：高频段能量占比偏离基线 0.38，判断 critical，建议切换备用泵——每个结论背后都挂着证据引用，证据审核 Agent 复核通过才会显示。我们还给它加了问答框：船员问"目前怎么样"，本地大脑（Qwen3-4B，在 GB10 上约 3 秒）汇总四路观测作答，全程不联网。

顺带一提，值班台前端是我们把交接文档写给另一个 AI 实现、再由我们做三重验收（它的单测、我们的 34 项评测、截图渲染确认）的一次真实多 AI 协作——**交接文档的质量决定了 AI 协作的质量**，这个体会和 Skill 工程的体会是相通的。

## 我们的 Skill 治理方法：把"发布纪律"变成工具

九天里我们给 Skill 体系沉淀了三件治理工具，这也是我们对"Skills 设计与融合"这个评审维度的回答：

1. **触发契约**：每个 Skill 声明正触发词（6–12 个）与负触发词（3–7 个），路由器对负触发命中扣分——"播报告警"路由到语音播报而不是报告生成，靠的就是这套消歧。
2. **输出契约**：每个 Skill 附 contract.json，Harness 强校验，残缺结果不进下游。
3. **skill lint**：对 15 个 Skill（9 自研 + 6 官方）执行 106 项结构检查（触发互斥、负向用例占比、契约、渐进式披露长度），当前 16/16 健康。

这三件事的动机来自官方生态的启发：NVIDIA 给 Skill 建了"扫描-评测-签名-文档"的发布纪律，我们把其中可本地化的部分变成了自己的工具。

## 数字总账

- **34 项评测用例**在 Windows 与 GB10 真机双端全部通过
- 声学全量对照：启发式三机种 0.687 / 0.777 / 0.630，且仅需 200 条建基线（数据效率高一个量级）
- 雷达 CA-CFAR：两目标方位/距离与真值精确吻合，空海面零虚警
- 视觉读数 MAE 2.0%（130 张参数化合成表盘）
- COLREGs 会遇态势分类自检 5/5（对遇/交叉/追越区间判定）
- 声纹分类 0.431（DeepShip 四类按文件划分，防同船泄漏）——这是最弱的数字，我们如实写进报告
- 60 秒宣传片：画面全部来自真实 Skill 输出，音效 numpy 合成，配音 SAPI——零外部素材，全链路一条命令可复现

## 结语：把智能留在船上

九天里我们装了六个官方 Skill、写了九个自己的、搞挂过一次节点、发现过一个反直觉现象、合成过一部没有外部素材的宣传片。如果要说这九天最大的收获，是我们的架构判断从来没变过：**推理可以分层，模型可以切换，但数据不出船、证据必须可查、不确定就要说不确定**。

智慧留在船上——这是 ShipMind 的名字含义，也是我们理解的边缘 AI 该有的样子。
