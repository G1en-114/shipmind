# 十日谈 · Day 1（2026-09-21 上午）：上真机，34 项评测全绿

> 本文是"十日谈"第二篇。[前一篇：为什么是一条船](链接)。

## 组委会的算力，第一印象

昨晚拿到了组委会分配的 DGX Spark 云节点。今天上午做的第一件事是**摸清这台机器的脾气**：GB10、ARM64、121GB 统一内存（CPU 和 GPU 共用这个池子）、20 核、3.7TB 盘、预置 vLLM 0.25 镜像 + torch 2.11 + CUDA 13。

"统一内存"这四个字后面会反复出现——它既是 DGX Spark 的卖点，也是最大的坑（后面 Day 2 晚上会讲到我们怎么栽进去的）。

## 官方 Skill：装了六个，只真跑了一个

下午把 NVIDIA 官方 Skill 目录搬了下来（367 个 Skill，pin 在 commit `fd9f1466`），装了六个和项目相关的：RAG Blueprint、TAO 图像定位、TAO 指代表达、VSS 视频问答、VSS 报告生成、DeepStream 管线生成。

诚实地说：**只有一个真跑了**——DeepStream 管线生成器有零依赖脚本，输入"处理一段 mp4 并做推理"，返回了真实的 `gst-launch-1.0 ... nvinfer ...` 管线命令。其余五个是"指令型"的：SKILL.md 里写着怎么部署 RAG Blueprint、怎么跑 TAO 管线，但需要 NGC key、TAO 容器、VSS 服务这些前置条件，我们没申请齐，就没有假装它们能跑。

这个"如实标注边界"的选择后来被证明是对的：评审问起来，我们能说清楚每个 Skill 到底是"真调用了"还是"作为设计参照"——比含糊其辞强得多。

## 34 项评测：我们在 DGX Spark 上全绿

傍晚把自研骨架推上节点跑了全量评测：**34/34 全绿**。包含 9 个自研 Skill（声学哨兵、航线偏离、雷达 PPI、声纹、值班日志、视觉巡检、手册 RAG、报告生成、verifier）的正向/负向/边界用例。

负向用例和正向同等重要——比如"今天晚饭吃什么"必须不触发任何 Skill（大脑负向路由），"纯噪声"声纹必须判 unknown 不硬凑船型，"空海面"雷达必须零虚警。这些"不触发"的用例比"触发"的更难写，也更能说明系统可靠。

## 踩坑与规避（给后来者）

- 官方 Skill 目录 367 个，**务必 pin 上游 commit**（我们钉在 `fd9f1466`）并保留每个 Skill 的 `skill.oms.sig` 签名和 `skill-card.md`——这是"我们真的用了官方 Skill"的证据链。
- 节点连不上 GitHub / HuggingFace / Zenodo。数据走本地下载后同步，模型走 ModelScope。
- 系统 Python 没 numpy，装的时候记得 `--break-system-packages`（Ubuntu 24.04 的 PEP 668 限制）。
