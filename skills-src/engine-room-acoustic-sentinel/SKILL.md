# 机舱声学异常哨兵

从一段机舱设备音频中判断是否存在异常，给出分级告警、可能成因与依据，并输出可被下游 Skill 消费的结构化结果。

## 前置提问（参数缺失必须先问，禁止猜测）

执行前确认以下四项，缺任何一项都要向用户提问，不得自行假设：

1. **音频文件路径**：本地音频文件（wav/flac/mp3）或已解帧的音频片段目录。
2. **设备类型**：主机 / 辅机 / 泵 / 轴承 / 风机 / 分油机 —— 决定使用哪套基线特征与阈值。
3. **运行工况**：额定 / 部分负载 / 启停过程 —— 同一特征在不同工况下阈值不同。
4. **基线来源**：该设备的历史正常录音目录，或明确的"无基线，仅做绝对阈值判定"。

## 执行流程

1. **输入校验**：确认音频存在、采样率与时长满足最低要求（≥ 5 秒，采样率 ≥ 16kHz）；不满足则停止并说明原因，不做"尽力而为"的模糊结论。
2. **特征提取**：运行 `scripts/acoustic_sentinel.py extract`，提取时域/频域特征与梅尔频谱统计量。
3. **基线对比**：运行 `scripts/acoustic_sentinel.py compare`，与基线目录比对，输出偏离度。
4. **分级判定**：按偏离度与规则给出 `normal` / `watch` / `alarm` / `critical` 四级，每级必须附带触发它的具体特征名与数值。
5. **成因提示**：调用 `colregs-qa` 之外的知识 Skill（设备手册 RAG）检索对应故障现象，给出可能成因列表与手册章节引用；检索不到就明确说"手册中未找到"，不得编造。
6. **语音播报**：将告警与处置建议交给 StepAudio TTS，机舱噪音环境下优先播报分级与动作，不播报技术细节。
7. **输出**：按下方契约写出结果文件。

## 禁止行为

- 禁止在缺少基线时给出"设备正常"的结论 —— 只能说"未检测到明显异常，但无基线可比"。
- 禁止给出超出声学证据的判断（如"轴承已损坏需更换"），只能给"存在异常，建议结合振动与温度复核"。
- 禁止凭空编造手册章节号或引用；引用必须来自 RAG 检索结果原文。
- 禁止在告警文案中包含推测性的责任归因或人身评价。

## 输出契约

结果写入 `output/acoustic_result.json`，结构如下；最终回复的最后一个非空行必须是纯文本路径行，确保文件真正回传给用户：

```json
{
  "device_type": "pump",
  "condition": "partial_load",
  "level": "alarm",
  "evidence": [
    { "feature": "band_energy_ratio_2k_4k", "value": 0.41, "baseline": 0.22, "delta": 0.19 }
  ],
  "possible_causes": ["轴承磨损", "叶轮气蚀"],
  "manual_refs": [{ "source": "主机运维手册", "section": "4.2.3", "quote": "……" }],
  "audio_clip": "output/anomaly_segment.wav"
}
```

最终回复末尾追加：`MEDIA:<结果json的绝对路径>`

## 评测

评测集见 `evals/cases.jsonl`，每轮必须包含：

- 正向用例：已知异常音频，期望 `level >= watch` 且 evidence 命中预期特征。
- 负向用例：正常音频，期望 `level == normal`（**不可触发比触发更重要**）。
- 边界用例：无基线、时长不足、工况不匹配，期望明确拒绝而非模糊结论。
