**船舶离线值守多智能体副驾**

> NVIDIA DGX Spark Hackathon · Agent Skills 开发挑战赛

## 摘要

ShipMind 是一套完全运行在 NVIDIA DGX Spark 船端设备上的多智能体值守系统：机舱内听异响、看仪表、查手册、说处置、记日志；驾驶台外读雷达、辨声纹、守航线。系统由 9 个自研 Agent Skill、6 个接入编排层的 NVIDIA 官方 Skill、一个自研 Harness（Skill 运行时/路由/契约校验/轨迹回放）和一个可双端点切换的编排大脑组成，34 项评测用例在 Windows 与 GB10 真机双端全部通过。本项目在声学异常检测上完成启发式与自编码器的全量对照并发现真实数据上的"误差倒挂"现象，在雷达检测上实现真值吻合、零虚警的 CA-CFAR，并坚持"每一帧、每个结论都有出处"的证据链纪律。

## 1. 背景与问题

### 1.1 行业痛点

远洋商船（货轮、油轮、LNG 船）的机舱与驾驶台值班高度依赖人力：

- **机舱**：轮机员夜间独自值守，轴承磨损、泵阀气蚀等故障靠耳听判断；设备手册为外文大部头，报警时翻检困难；轮机日志手工填写，PSC（港口国监督）检查时翻查耗时。
- **驾驶台**：夜航雾航瞭望疲劳易漏检小目标；雷达光点依赖人眼连续监视；COLREGs 避碰条款临场靠记忆。
- **文书**：航海/轮机日志手工誊写，易漏易错。

### 1.2 为什么必须本地部署

| 论据 | 说明 |
|---|---|
| **合规硬约束** | 《海上交通安全法》第二十四条：船舶在我国管辖海域通信须通过依法设置的境内海岸无线电台或卫星关口站转接。机舱音视频、AIS、航线数据船内闭环是合规风险最低的架构 |
| **带宽经济学** | 卫星链路按流量计费，多路音视频持续上云推理在带宽与费用上均不可行 |
| **时延与可靠性** | 机舱告警需秒级响应，卫星链路存在抖动与中断，安全系统不能依赖单一天线链路 |
| **数据主权** | 航线、AIS、机舱数据是船东核心商业资产，不应出境 |

### 1.3 政策环境（已核实）

《智能船舶发展行动计划（2019—2021年）》由工业和信息化部、交通运输部、国防科工局联合印发；中国船级社《智能船舶规范》2026 版已于 2026-06-01 生效，明确智能集成平台承担全船数据采集共享。智能船舶方向政策顺风。

## 2. 系统架构

```
船员（语音/触屏） ←→ 语音链路（step-tts-2 / step-asr）
        ↕
主 Agent 编排路由 —— 双端点大脑
   本地：Qwen3-4B-FP8（vLLM 0.25，GB10，离线）
   在线：step-3.7-flash（StepFun API，262K+视觉）
        ↕
Skill 层（15 个）
   自研 9：声学哨兵 / 视觉巡检 / 手册RAG / 值班日志 / 巡检报告
           声纹 / 雷达PPI / 航线偏离 / 语音播报
   官方 6：deepstream-generate-pipeline（真执行）
           rag-blueprint / tao×2 / vss×2（advisory，前置条件如实标注）
        ↕
证据审核 Agent（verifier）：逐条核对结论↔证据，无证据即驳回
        ↕
自研 Harness：Skill 运行时 · 路由（大脑优先/关键词兜底/负触发避让）
              · 输出契约校验 · 执行轨迹录制回放 · 算力调度
        ↕
值班台 Web：告警流 · 频谱 · 带框截图 · 雷达态势 · 手册检索 · 报告 · 轨迹回放
        ↕
传感器接入层（模拟源映射真实设备）
   音频（MIMII/DeepShip）· 视频（MODD2 真实 USV）· NMEA 模拟器 · PPI 合成器
```

**运行时零云端依赖**；开发期使用组委会分配的 Spark 云节点。

## 3. 关键技术实现

### 3.1 Agent Skill 体系（15 个 Skill 的设计与治理）

**触发契约**：每个自研 Skill 在 frontmatter 声明正触发词（6–12 个）与负触发词（3–7 个），路由器对负触发命中扣分——语义冲突时宁可少分也不误触发。实测消歧："播报告警"→ 语音播报，"生成巡检报告"→ 报告生成，四组正反例全对。

**输出契约**：每个 Skill 附 `contract.json` 声明必填字段与类型，Harness 强校验——残缺结果不得进入下游。

**渐进式披露**：常驻仅 name + description（≤400 字符），正文与脚本按需加载。

**skill lint**：自研健康检查器，对 15 个 Skill 执行 106 项结构检查（触发互斥、契约、负向用例占比、可执行状态），当前 16/16 健康。

### 3.2 多智能体协同

跨线融合链路：雷达目标 × 声纹船类 × 航线态势 × COLREGs 态势分类 → 条款原文检索 → 五条结论各挂证据引用 → **证据审核 Agent（verifier）逐条复核**（引用存在性 + 非空校验，无证据即驳回并标注"待复核"）→ 语音播报 + 态势报告 + 自动日志。COLREGs 会遇态势分类为确定性函数（对遇 ≤5° 且反向、追越 >112.5°、交叉其余右舷让路，区间参照 Zhao & Roh 2019），自检 5/5。

### 3.3 编排大脑：双端点可切换

| 端点 | 模型 | 网络 | 验证 |
|---|---|---|---|
| 本地（离线） | Qwen3-4B-FP8（vLLM 0.25，GB10） | 无 | 路由三连含负例通过 |
| 在线 | step-3.7-flash（StepFun API） | 需网络 | 同一用例集行为一致 |

切换仅改 `base_url / model_name / api_key` 三值。step-3.7-flash（198B）无法在 GB10 本地部署：FP8 权重 198GB 超出 121GB 统一内存，NVFP4 约 105GB 后 KV cache 无剩余量，且节点 vLLM 0.25 不支持该架构（PyPI 无 aarch64 wheel、节点无 nvcc、GitHub 不可达）。离线场景自动降级本地端点。

### 3.4 自研 Harness

- **执行轨迹**：每次 Skill 执行的输入/输出/耗时落 JSONL，支持回放与两次执行的字段级 diff——"像调试二进制程序一样调试 Agent"。
- **本地算力调度**：GB10 统一内存架构下显存预算显式管理（实测默认 0.9 配置会耗尽 121GB 触发整机 OOM，已固化为 0.45 + enforce-eager + flashinfer 版本检查绕过）。

## 4. 评测结果

### 4.1 系统级

**34 项评测用例在 Windows 与 GB10 真机双端全部通过**，覆盖 9 个自研 Skill 的正向/负向/边界场景，其中负向用例（不该触发时必须不触发、空海面零虚警、语料外问题拒绝编造、脏数据整体拒绝）与正向同等重要。

### 4.2 机舱声学异常检测：双轨全量对照

数据：DCASE 2020 Task 2 开发集（MIMII，CC BY-NC-SA），全量 test 集。

| 机种 | 启发式轨（z-score 偏离） | ML 轨 AE（偏离度口径） | 测试规模 |
|---|---|---|---|
| pump | **0.687** | 0.602 | 400 正 + 456 异 |
| valve | **0.777** | 0.490 | 400 正 + 479 异 |
| fan | **0.630** | 0.529 | 400 正 + 1475 异 |

三项结论：
1. **启发式轨全面胜出**，且数据效率高一个量级（200 条建基线 vs 全量训练集）——对"一条船只有少量历史录音"的真实场景有实际意义。
2. **发现"误差倒挂"**：带符号重构误差在 pump 上 AUC 仅 0.260，因该子集异常为"信号变更弱"，AE 将异常重建得更好；改用方向无关偏离度后恢复。证伪了"异常=重构误差更高"的默认假设，两种口径同时报告不藏结果。
3. 简化 AE 的上限来自实现而非方法（无 BatchNorm、SGD、30 epoch vs 官方 Keras+Adam+100 epoch）——如实标注。

### 4.3 声纹分类

DeepShip 四类（46 文件、1512 片段），LOFAR/DEMON 特征 + 逻辑回归，**按文件划分防同船泄漏**，测试集准确率 0.431（4 类随机 0.25）。规则轨标签体系与 DeepShip 不对等（0.24），仅作量级参考。局限如实标注：GitHub 部分版数据量有限。

### 4.4 视觉读数

130 张参数化合成表盘（脏污/眩光/遮挡退化），红/黑指针双路检测 + 显著性过滤 + 双峰歧义拒判：归一化读数 MAE **0.020**，模糊样本拒判而非猜测。升级轨（TAO grounding + VLM 量程识别）接口一致保留。

### 4.5 雷达检测

逐方位线 1D 距离向 CA-CFAR（双噪声模型：高斯 RMS 匹配合成器、指数包络匹配真实雷达功率数据）：两目标方位/距离与真值精确吻合（44.9°/3000m、209.9°/6000m），空海面**零虚警**。

### 4.6 编排回归

本地端点与 StepFun API 端点跑同一用例集（两正一负含负例），**6/6 行为一致**。

## 5. 创新点

1. **合规驱动的架构**：以法条而非成本作为本地部署的第一论据，属行业内少见的论证路径。
2. **证据链纪律**：verifier 独立于生成方复核"结论↔证据"，无证据结论在报告中标注"待复核"而非静默删除——对齐 TAO referring-expressions 的 double_check 模式。
3. **双轨对照的诚实报告**：启发式与 ML 同特征同口径对照，负向结果（AE 倒挂）与正向结果同等呈现。
4. **零外部素材宣传片**：60 秒成片的画面全部来自真实 Skill 输出、音效全部 numpy 合成、配音 SAPI，全链路一条命令可复现。
5. **Skill 治理工具化**：触发契约 + 负触发避让 + skill lint（106 项检查），将官方"发布纪律"内化为本地工程实践。

## 7. 部署说明

1. 硬件：DGX Spark（GB10，ARM64），121GB 统一内存。
2. 推理端点：vLLM 0.25 容器，`--gpu-memory-utilization 0.45 --enforce-eager`，`VLLM_USE_DEEP_GEMM=0`，`FLASHINFER_DISABLE_VERSION_CHECK=1`（统一内存架构必须显式限容，默认 0.9 会触发整机 OOM——实测事故已记录）。
3. 官方 Skill：skills CLI（≥1.5.16）安装后 vendored 入仓库，桥接层双模式派发（executable 真跑 / advisory 展开）。
4. 数据：评测夹具由 `evals/make_fixtures.py` 确定性生成，不入仓库；真实数据集按许可台账管理（CC BY-NC-SA 等），音频不进 git。
5. 安全：所有服务仅绑 127.0.0.1；凭据经环境变量注入，不入仓库；提交前密钥扫描。

## 8. 局限与展望

**局限（如实声明）**：
- 数据以公开数据集与仿真源为主，未上船实测；雷达 PPI 与 NMEA 为合成数据。
- 声纹 ML 准确率 0.431（4 类），受限于 DeepShip 公开部分的数据规模。
- 语音链路当前经 StepFun API，非本地（如实标注）；完全离线场景下语音降级为文本。
- 官方 Skill 中 5 个为 advisory 接入（需 NGC/TAO/VSS 栈），仅 1 个真执行。
- 本地大脑为 4B 级，复杂研判深度弱于在线 198B 模型。

**展望**：
- DeepShip 完整版 + ShipsEar 申请中，数据到位后重训声纹分类器。
- TAO/NeMo 微调表盘量程识别 VLM，打通视觉绝对读数。
- DeepStream runtime 实跑 MODD2 真实 USV 视频（mp4 已合成）。
- 架构平移：海上风电运维船、港口机械、海洋平台、内河船队。
